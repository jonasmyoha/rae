# QUEUE: Physics port (Box3D -> Rae)

The phased tasks of the Box3D port, P0-P10. The design and the reasons for
the phase order are in docs/physics-rae-port-design.md; each task names the
sections it implements. The phases are sequential: P0 first, and each later
phase builds on the one before.

SUMU runs only the root QUEUE.md. To run a phase, move its line (with its
`#id`) back between the SUMU markers in QUEUE.md; record the outcome there as
usual.

- [ ] #69624965 {difficulty:4} [physics port P0 — prerequisites] docs/physics-rae-port-design.md §4, §7 P0. (1) Pass `-ffp-contract=off` in EVERY Rae C compile (rae run/build, the run_examples.sh and run_tests.sh gcc lines, wasm_build.sh, the emit-c recipes in docs) and add a fixture that fails if `a * b + c` is contracted to an FMA (compare against a value that differs by the FMA rounding). (2) `countTrailingZeros(this: UInt64) ret Int` (and `Int32`/`UInt32` variants if cheap) as a compiler intrinsic over `__builtin_ctzll` (recommended, design §9 Q2) with a fixture. (3) `tools/box3d-oracle/`: a script that clones github.com/erincatto/box3d at commit 9f998c8 into a cache dir OUTSIDE the repo, builds it scalar (`BOX3D_DISABLE_SIMD`, `-ffp-contract=off`, workerCount 1) with a small C driver, and writes golden traces as hex floats; first golden: the math functions (vector/quat/transform ops, b3Atan2, b3ComputeCosSin over a fixed input set). No C lands in lib/ or third_party/. (4) Measure `List.modAt` in a tight loop vs a raw Buffer on 100k structs and record the ratio in the design doc §6.
- [ ] #10659746 {difficulty:5} [physics port P1 — math] docs/physics-rae-port-design.md §3, §7 P1. Port Box3D's math layer (include/box3d/math_functions.h, src/math_functions.c, src/math_internal.h, constants.h) to lib/physics/math/ following the §3 porting rules (Rae names, Float = f32, operation order preserved, deterministic atan2/cos/sin ported verbatim). A fixture compares every function against the P0 oracle golden BIT-EXACT (hex floats). Needs P0.
- [ ] #82679768 {difficulty:5} [physics port P2 — convex geometry and narrow phase] docs/physics-rae-port-design.md §7 P2. Port aabb, sphere, capsule, hull (quickhull construction), distance (GJK distance, shape cast, segment distance) and the convex manifolds (manifold.c, convex_manifold.c SAT) to lib/physics/geometry and lib/physics/collision. Shape-pair dispatch is an exhaustive `match` (no function-pointer table). Oracle goldens per module (hull from point clouds, distance/cast between shape pairs, manifolds for sphere/capsule/hull pairs); fixtures bit-exact. Split into more tasks if it does not fit one turn. Needs P1.
- [ ] #92914998 {difficulty:5} [physics port P3 — broad phase] docs/physics-rae-port-design.md §7 P3. Port dynamic_tree (insert, remove, move, rebuild, AABB and ray queries), broad_phase (pair finding, the pair set — a Rae open-addressing map keyed by the UInt64 pair key, replacing verstable.h), bitset, id_pool and qsort.h (ported as written: sort order is part of the result). Oracle goldens for tree queries after a scripted insert/move/remove sequence and for the pair list; fixtures bit-exact. Needs P1.
- [ ] #57738019 {difficulty:5} [physics port P4 — the first world] docs/physics-rae-port-design.md §7 P4. Port body, shape, contact, solver_set, island (sleep), constraint_graph (colouring), solver and contact_solver (SCALAR path: a wide float is a struct of four Floats), sensor, physics_world (step, events) and types.c into lib/physics/dynamics, with all world state on a PhysicsWorld value (no globals). Scenes bit-exact against the oracle for 600 steps: a sphere falling on a box, restitution, friction on a 20-degree slope, a 10-level box pyramid, contact and sensor events. Split into more tasks if needed. Needs P2 and P3.

- [ ] #22610309 {difficulty:5} [physics port P6 — joints] docs/physics-rae-port-design.md §7 P6. One oracle scene per joint kind (a hinged plank to its limit, a pendulum, a wheel on a suspension) bit-exact. Needs P4.

Port the world queries (closest ray cast, shape cast, AABB/shape overlap) and the mover primitives (mover.c: cast mover, collide mover, solve planes, clip vector), then write the character loop from samples/mover.cpp in Rae (slide along walls, step a 0.3 m curb, blocked by 0.6 m, grounded + ground normal on a 20-degree ramp — the scenes of docs/physics-design.md §7). - [ ] #30855232 {difficulty:4} [physics port P8 — the ECS layer] docs/physics-rae-port-design.md §7 P8 and docs/physics-design.md §5.1–5.5. lib/physics/ecs: the PhysicsWorld resource (fixed step, substeps, event queues, static venue shapes), RigidBody / Collider / CharacterBody components, the push / step / pull / event / character systems in the fixed-step schedule, spawnRigidBody / despawnRigidBody (destroy the body before the entity's components are cleared), static venue colliders from MeshData. Port upstream's benchmark scenes (benchmark/main.c: the large pyramid, the joint grid, the many-tumblers style scenes) as Rae programs printing step time; compare with the oracle's C scalar build on the same machine; target the Rae port within 1.5x single-threaded at -O2 (design §9 Q1).
