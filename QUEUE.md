- [ ] #662 Plain-`let` `view`/`mod` binding on a primitive `viewAt`/`modAt` miscompiles — only `if let` was covered by #653. Motivation: #653 verified `if let x: view/mod <Int|Float|Bool> => list.viewAt/modAt(index:)` lowers correctly (the `emit_list_if_let` peephole emits `rae_View_Int64 x = { .ptr = &__rae_list->data[i] }`). But the PLAIN `let x: view/mod <Prim> => list.viewAt/modAt(index:)` form — auto-unwrapping the returned `opt view/mod T` — does NOT go through that peephole. It calls the real monomorphized accessor, which returns a raw `const int64_t*`/`const float*` (the `opt view Int`/`opt view Float` lowering), and assigns it straight into the primitive view WRAPPER local, so the C compiler rejects it:
  `error: initializing 'rae_View_Int64' with an expression of incompatible type 'const int64_t *'`
  (also `rae_View_Float` from `const float *`). Repro: the downstream access-mode sweep (formerly #112, in a game repo) emits ~25 such plain-`let` scalar reads over `List(Int)`/`List(Float)` (e.g. `let a0: view Int => wire.viewAt(index: 0)`, four in a row for a packet decode) and NONE of them compile; the 8 `if let` primitive-view sites in the same app DO compile (per #653). Root cause: `view <primitive>` as a LOCAL lowers to the wrapper struct `rae_View_Int64 { int64_t* ptr }` (rae_runtime.h:229/240), but the plain-`let` binding path assigns the raw pointer (accessor return / opt-view unwrap) WITHOUT the `{ .ptr = ... }` wrap. Struct element types are unaffected (`view <struct>` is itself a raw `T*`, which matches the raw-pointer return — that is why #112's struct `viewAt` sites compiled). Also INCONSISTENT with #642: the `=` value form (`let x: T = list.copyAt(...)`, opt→non-opt) is a clean sema error directing to `if let`, but the `=>` view/mod form on an optional slips past that check and reaches codegen. Scope — decide in review: (a) make the plain-`let x: view/mod Prim => list.viewAt/modAt(...)` path wrap the pointer into `rae_View_T`/`rae_Mod_T` (extend the opt-view unwrap / peephole to the plain-`let` binding, not just `if let`), OR (b) for consistency with #642 ("every optional ends in `if let`"), make a plain-`let ... => <opt view/mod T>` a clean sema error whose message says the accessor returns an optional — use `if let` (since `viewAt`/`modAt` return `opt view/mod T`). (b) is the consistent choice given #642, but forces the downstream app to wrap every scalar read in `if let`; (a) keeps the terse `let a0: view Int => ...` read working. Acceptance: a plain-`let x: view/mod <Int|Float|Bool> => list.viewAt/modAt(index:)` either compiles to a correct `rae_View_T`/`rae_Mod_T` pointer wrapper (mod round-trip test) OR errors at the .rae call site with a message pointing to `if let` — NOT a downstream C-level type error; tests for both `view` and `mod`, `Int` and `Float`, in the plain-`let` form; the downstream app's plain-`let` scalar reads then resolve (or are told exactly how to). Deps: follows #653 (which covered only the `if let` form); relates to #642 (opt-unwrap rule) and #657 (clean sema errors instead of C errors).
