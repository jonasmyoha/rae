# T013 - Compiler C backend plan & bootstrap

## Summary
- Captured the end-to-end C backend roadmap in `docs/c-backend-plan.md`, outlining milestones (stub CLI, emitter scopes, runtime) and how the existing frontend is shared between interpreter + compiler.
- Added `build` support to `rae/compiler/src/main.c`, including `--entry`, `--project`, `--out`, and `--emit-c` flag parsing plus file/dir validation for the new CLI surface.
- Wired `rae build --emit-c` through the ModuleGraph so it emits real C via `c_backend_emit`, reusing the parser/AST that powers the VM interpreter path.
- Regenerated the golden outputs for the build-related regression cases (400–405) so tests assert the emitted C stays stable.
- Documented the ModuleGraph ordering/diagnostics expectations and future manifest hand-off inside `docs/c-backend-plan.md`.
- Hardened `rae build --emit-c` so it now creates the parent directory for `--out` before invoking the backend, keeping nested paths working without manual prep.
- Expanded the plan with a dedicated front-end parity section plus stub-behavior notes so Live + Compiled share identical pipelines.
- Added a CLI fallback that writes a clearly-labeled stub C file (and manifest) whenever the experimental backend cannot emit code yet, so tooling still has deterministic artifacts.
- Added metadata-driven example actions plus UI plumbing so the hybrid demo exposes **Simulate dev/release download** buttons that call the helper, stream log output, and list the staged `.vmchunk` hashes directly in the dashboard.
- Created `examples/hybrid_hot_reload/scripts/simulate_download.sh`, which builds dev/release hybrid bundles, copies their VM artifacts into `.simulated_downloads/`, and prints the resulting manifest/hash summary for the dashboard.
- Updated `compiler/tools/run_tests.sh` to honor `TARGET=compiled|hybrid`, limiting those dashboard test runs to the new build-specific regressions so Compiled/Hybrid switches stay fast.
- Versioned the hot-reload patches (`version1/2/3`) and expanded the example actions so dev/release downloads can be staged per version, keeping repeated reloads easy to demo.
- The staged downloads list now groups bundles by profile + version so the UI makes each iteration explicit.
