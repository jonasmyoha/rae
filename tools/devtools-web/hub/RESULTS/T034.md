# Task T034 - VM research and fixing it with smaller steps

## Summary
Investigated and fixed stack leak and corruption issues in the bytecode VM.

## Changes
- **Stack size increase**: Increased `stack` and `call_stack` size from 256 to 1024 to allow larger programs to run safely.
- **Stack balancing**: Added missing `OP_POP` instructions after `OP_SET_LOCAL` in `AST_STMT_DEF`, `AST_EXPR_MATCH`, and `AST_STMT_MATCH`. This prevents the stack from growing on every variable definition or match expression.
- **Idempotent allocation**: Modified `OP_ALLOC_LOCAL` to use absolute required counts and updated the VM to only grow the slot count if necessary. This fixes a leak where `OP_ALLOC_LOCAL` inside a loop would grow the stack on every iteration.
- **Regression Test**: Added `321_stack_leak.rae` which executes a loop 5000 times with a local definition, verifying that the stack no longer overflows even with a 1024-slot limit.

## Results
- `cd rae/compiler && make test` passes all 73 tests.
- Memory corruption from previous `value_free` attempts was avoided by reverting those changes and focusing on the logical stack leaks first.
