# Task T049 - Parser: Generic Parameters on Type and Function Declarations

## Summary
Implemented support for parsing and formatting generic parameters on type and function declarations in Rae, ensuring correct representation of generic arguments in the AST.

## Changes
- **`ast.h`**:
    - `AstTypeDecl` and `AstFuncDecl` now include `AstIdentifierPart* generic_params` to represent generic type names like `T`, `K`, `V`.
    - `AstTypeRef` was modified to include `struct AstTypeRef* next;` to enable linking multiple generic type arguments at the same level.
- **`parser.c`**:
    - Implemented `parse_generic_params` to handle parsing the `[T, K, V]` syntax for generic parameters, using `AstIdentifierPart` for storage.
    - Modified `parse_type_declaration` and `parse_func_declaration` to call `parse_generic_params` and store the result.
    - Modified `parse_type_ref` to correctly parse generic parameters as a linked list of `AstTypeRef` using the `generic_args` field, addressing the issue of `Int[String]` misinterpretation.
- **`ast.c`**:
    - Updated `dump_type_decl` and `dump_func_decl` to correctly display the generic parameters in the AST dump.
    - Updated `dump_type_ref` to correctly traverse and display the linked list of generic arguments (`type->generic_args`).
- **`pretty.c`**:
    - Updated `pp_print_type_decl` and `pp_print_func_decl` to correctly format generic parameters.
    - Updated `pp_write_type` to correctly format `AstTypeRef->generic_args` and `AstTypeRef->next` linked list.

## Acceptance
- `type MyType[T, K] { value: T }` and `func identity[T](value: T): ret T { ret value }` parse and format correctly, as verified by `rae format`.
- Generic type references like `MyType[Int, String]` are now correctly parsed and formatted without misinterpreting nested generics.
