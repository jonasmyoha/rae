# Task T050 - Parser: Collection Literal Parsing `List[T]{ ... }` and `{ ... }`

## Summary
Implemented support for parsing and formatting collection literals (List and Map) and their formatting. This includes disambiguation between list-like and map-like literals, and correctly handling both string and identifier keys.

## Changes
- **`ast.h`**:
    - Added `AST_EXPR_COLLECTION_LITERAL` to `AstExprKind`.
    - Added `AstCollectionElement` and `AstCollectionLiteral` structs to represent collection elements and the literal itself.
    - Updated `AstExpr` union to include `AstCollectionLiteral collection;`.
- **`parser.c`**:
    - `append_collection_element` function defined (no longer static).
    - Implemented `parse_collection_literal` to parse `{ ... }` syntax, correctly distinguishing between keyed (Map) and unkeyed (List) elements.
    - Modified `parse_primary` to call `parse_collection_literal` when `TOK_LBRACE` is encountered, effectively parsing `{ ... }` as a collection literal in expression position.
    - Added `TOK_STRING` as a valid key type for map literals in `parse_collection_literal`.
    - Refined loop handling in `parse_collection_literal` to correctly consume commas and break on `TOK_RBRACE`.
- **`ast.c`**:
    - Added `AST_EXPR_COLLECTION_LITERAL` case to `dump_expr` for detailed printing of collection elements.
- **`pretty.c`**:
    - Added `AST_EXPR_COLLECTION_LITERAL` case to `pp_expr_prec` for formatting collection literals with `{ }` and comma-separated elements, including `key: value` pairs for maps.
    - Defined `PREC_ATOMIC` in `Precedence` enum to resolve undeclared identifier error.

## Acceptance
- `def x: List[Int] = { 1, 2, 3 }` parses and formats correctly.
- `def y: Map[String, Int] = { "a": 1, "b": 2 }` parses and formats correctly.
- The parser correctly identifies `{ ... }` as a collection literal in expression position and distinguishes between list and map literals.
