Time to send one message to every client

A chat-style broadcast: one client sends a message, the server sends it to every connected client and then confirms to the sender. The time is that round trip (p50, median of 3 ramps). It grows with the number of clients, by 4.3–4.8 ms per 1 000, for every server alike.

Bun and Node, both on uWebSockets (C++), use the least memory. Stacks: Rust: own framing on tokio, corked writes; Node: uWebSockets.js, publish; Bun: Bun.serve websockets, publish; Rae: lib/net and lib/webSocket, written in Rae.

How it was measured

Apple M1 Max (8 performance cores), macOS 27.0. rae 0.1.268-dev.3730+dirty, rustc 1.93.1 (01f6ddf75 2026-02-11), Node v26.5.1, Bun 1.3.5. The servers run interleaved on the same machine, one load client for all, and each must pass the same correctness checks (check.sh) before it is timed. The load client shares the machine, and the load average was 5.3 at the start: absolute numbers may sit a few percent low, but every server ran under the same load. The Rust, Node and Bun servers are the tuned versions (2026-10-11). Full numbers, method and fairness notes: benchmarks/servers/README.md; regenerate with benchmarks/servers/run.sh, then python3 benchmarks/servers/generateSite.py.
